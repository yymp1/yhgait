# 步态检索闭环分析结果

## 本轮真实做了什么

1. 真实读取 `00500` 与 `01000` 的 gait demo cache
2. 在固定测试集 probe 上真实跑完 Top-5 检索分析
3. 统计 `Top-1 / Top-5` 与 `NM / BG / CL` 分组表现
4. 把 `00500` 与 `01000` 放到同一套 probe / gallery 协议下做对照

关键产物：

- `reports/gait_demo_analysis_iter00500.json`
- `reports/gait_demo_analysis_iter01000.json`

## “80%” 到底是什么意思

这次 GUI 里不能直接说“模型准确率 80%”。

更严谨的定义应该是：

- 固定测试集 probe 数量：`3298`
- probe 类型：`nm-05/06`、`bg-01/02`、`cl-01/02`
- gallery 类型：同视角 `nm-01~04`
- 统计口径：`Top-1` 或 `Top-5` 命中率

所以这里真正该看的，是固定测试集上的检索命中率，而不是随机抽样的肉眼感觉。

当前真实结果说明：

- `01000` 的全量固定测试集 `Top-5 = 71.19%`
- `01000` 的全量固定测试集 `Top-1 = 62.07%`

也就是说：

- 如果口头说“可见识别正确率大约 80%”，这在严格口径下 **不成立**
- 更接近的说法应该是：
  - `BG` 组 `Top-5` 接近 `80%`
  - 但全量 overall 并没有到 `80%`

## 同一批 probe 的改善/回退

`00500 -> 01000` 的同 probe 对照结果：

- Top-1 改善：`232`
- Top-1 回退：`54`
- Top-5 改善：`243`
- Top-5 回退：`49`

按 probe 组看，Top-1 改善主要来自：

- `BG`：`115`
- `CL`：`84`
- `NM`：`33`

这说明 `01000` 相比 `00500` 不是“只在个别样本上看起来更好”，而是在固定测试集上有真实、可统计的提升。

## 这和官方评估结果是什么关系

这套 GUI 分析结果和官方 `NM/BG/CL Rank-1` 不是同一个统计口径。

原因是：

- GUI 这里用的是“固定 probe + 同视角 `nm-01~04` gallery”的检索协议
- 官方评估用的是 OpenGait 评测流程里的 CASIA-B benchmark 协议

所以：

- GUI 里的 `62.07% / 71.19%` 用来说明“数据集检索页面能看见什么效果”
- 官方评估里的 `23.95 / 17.17 / 8.00` 用来说明“benchmark 口径下的正式评估结果”

两者都是真实结果，但不能混写成一个数字。
